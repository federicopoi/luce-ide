# Orbit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Install a tested local terminal-first Orbit.app on this Apple Silicon Mac.

**Architecture:** Electron owns storage, read-only provider history discovery, node-pty sessions and isolated WebContentsView previews. A sandboxed renderer uses a narrow preload bridge and xterm.js. Switching views does not stop processes.

**Tech Stack:** Electron 44, node-pty 1.1, xterm.js 6, esbuild, Node test runner, Playwright Electron tests, Electron packager.

**Spec:** ../specs/2026-10-01-orbit-design.md

## Global Constraints

- Source: `/Users/fedepoi/orbit`; installation: `/Users/fedepoi/Applications/Orbit.app`.
- Local Mac application; no remote/mobile access or automatic approval engine.
- Use installed Claude Code and Codex; never alter their credentials or permissions.
- Preview pages have no Node integration or Orbit bridge; sandbox and context isolation enabled.
- Persist metadata; switching views preserves terminals; Quit ends Orbit-owned processes with confirmation.
- Read provider histories only; use canonical recorded directories and safe CLI argument arrays.

## Review Focus

- Malformed/large histories: discovery must stay responsive and skip invalid records.
- Missing project folder/CLI: display an actionable error, preserve existing sessions.
- Spaces and shell metacharacters: cwd/IDs/labels cannot inject commands.
- Hostile preview navigation: cannot reach Orbit IPC, Node or privileged URL schemes.
- Project switches/reopened window: reuse live sessions without duplicate processes or lost output.
