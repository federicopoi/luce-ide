# Accounts and conversation switching implementation plan

Goal: Keep multiple Codex accounts authenticated, assign project defaults, switch one saved conversation between accounts, and show provider-reported quotas.

Architecture: Account metadata is persisted separately from credentials. Existing login stays in its original CODEX_HOME; new accounts have private directories and file credentials. A main-process JSON-RPC client owns one stdio app-server per account for login/status/quota only. Terminal PTYs receive their own account environment. Saved histories are indexed per account. Switching uses an explicit saved conversation ID (a picker for fresh terminals), stops only the selected PTY, copies the complete transcript to the target home, validates local read, then resumes it; unsupported formats use an explicitly marked text-context continuation. Claude reports quota through a per-terminal statusLine bridge without changing global settings.

Constraints: Never expose credentials to renderer; no inference during tests or account status reads; do not log out or mutate existing auth; no automatic switch mid-response; preserve source transcript; require explicit saved-conversation selection for fresh terminals. Account identity comes from account/read, not name. Missing quotas remain unavailable.

- [x] Account storage and JSON-RPC: tests for isolation, restart persistence, invalid IDs, secret-free status, timeout/process cleanup; implement accounts.cjs and codex-client.cjs.
- [x] History and terminals: tests for overlapping IDs across homes, full transcript copy and unknown/ambiguous sessions; add account metadata, per-launch environment, project defaults, switch service.
- [x] Claude quota: tests for documented JSON windows and stale/absent data; per-session bridge writes only sanitized percentages/reset timestamps with private file permissions.
- [x] UI/IPC: account manager dialog with add/name/sign-in/cancel/remove/refresh; project default menu; per-terminal account switch with confirmation and usage detail; account labels in histories. IPC validates IDs and account selection; external login URL restricted to provider HTTPS domains.
- [x] Verification: full unit suite, build, deterministic Electron account smoke with fake provider subprocess (no auth/inference), existing smoke/recents, real Codex read-only status probe, code review, package/install/signature checks and installed smoke.

Review focus: inherited API auth must not silently override managed ChatGPT account; switching preserves full latest history and rejects concurrent same thread; fresh unsaved/ambiguous conversations never guessed; account removal cannot break active terminals/project references or delete existing credentials; usage unavailable/stale never shown as zero.
